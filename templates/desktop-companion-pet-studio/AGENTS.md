# DesktopCompanion pet production

Apply these instructions to pet work, not unrelated runtime development.
Use the installed `crafting-desktop-companion-pets` skill. Read the chosen run's
existing state record first, then its brief, selected contracts and relevant skill
references. Preserve completed work; do not restart because a task resumed.

Inherit model, effort, role and concurrency settings from user-global Codex
configuration; do not install project routing overrides. Record actual model/effort
only when exposed by the host. Preserve login, provider, billing and permissions.
Use the business briefs in docs/agent-briefs/ as task context for suitable global
roles, not as installed agent definitions. Follow the global child cap and keep one
writer. The primary owns integration and final acceptance. Check live availability
and permissions; a brief's sandbox preference does not prove effective isolation.

Use built-in image generation by default and read the skill's execution-and-models
reference for model capabilities. API preferences do not authorize API billing;
do not infer the built-in image model from a configured name.

Keep confirmed style, scope and authority across turns. After internal gates pass,
continue authorized local production unless the user reserved a specific choice.
User acceptance of a specific image remains separate. A missing evidence item
blocks dependent work, not unrelated safe preparation. Retain all visual checks.

Use a separate run directory for each pet. Preserve the selected v2/v3/v4 route.
For a v3 deliverable, the actual package-root directory must match the pet ID;
validate the exact directory and bytes that will be handed off. Do not install,
publish, commit or push a pet merely because its local production was authorized.

Update the run's state with the next action, blockers and links to hash-bound
evidence after recoverable milestones. Do not treat the state index as a visual
or runtime validator. Keep private references, generated art and machine-local
files out of shared configuration changes unless separately in scope.
