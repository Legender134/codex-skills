# Nangong Wan Quality Standard

## Status of this reference

This is the primary production standard for every source-faithful DesktopCompanion character. Read it before planning a new character, even when the character is not similar to Nangong Wan and even when the final package is not v3.

Transfer the decision discipline, production order, visual thresholds, repair logic, and stopping rule. Do not copy Nangong Wan's character design or numerical parameters unless new evidence independently supports them.

When the current project explicitly links an approved Nangong Wan package, identity master, contact sheets, true-duration previews, review report, or test record, inspect those selected artifacts and record their hashes as the current tangible quality baseline. Do not search neighboring experiments or assume the newest timestamp is approved. If tangible artifacts are unavailable, use this written standard and report that limitation. Never copy Nangong Wan artwork into another character.

The evidence base ends at the historical point where the Nangong Wan single-form pet was assessed near 9/10, before later mouse-gaze/64-angle work, rooftop-and-moon states, showcase videos, and later release experiments.

## The quality contract

A high-quality pet must succeed as five connected products:

1. a recognizable version of the requested character;
2. a portfolio of actions that expresses that character rather than filling slots;
3. animation whose key poses, timing, props, and effects communicate complete actions;
4. a valid package that the real runtime can load and schedule;
5. a desktop companion that remains readable and pleasant during long use.

Passing one surface does not compensate for failure on another.

## Default production standard

### 1. Correct the target before drawing

Lock the exact continuity, era or episode range, form, costume, proportions, and exclusions. Current official animation governs current identity. Current official clips govern motion and effect continuity. Older official appearances of the same character may supply compatible motion grammar only where current evidence is missing; they never restore an old face, costume, palette, ability, or power level.

For each effect, prove the caster, emission point, travel, peak, decay, palette, and motif. Mixed battle footage requires an explicit effect whitelist and blacklist. “Fits the setting” is not ownership evidence.

The master remains provisional when current evidence cannot establish high-salience silhouette, face/age/mark, dominant costume blocks, and signature hair or ornaments.

### 2. Approve identity at desktop size

Create an identity master before action batches. Review it at the actual or explicitly provisional runtime scale on checker, light, and dark backgrounds. Lock silhouette, face, age impression, hair mass, ornaments, costume layers, palette, asymmetry, props, body occupancy, and anchor.

Preserve high-salience recognition before tertiary texture. Simplify small decoration before shrinking the body or blurring the face. A stylized or chibi route must preserve adult/child age impression and character-specific proportions.

### 3. Build an action portfolio by role

Use coverage, not a quota:

- persistent presence: idle, breathing, blink, temperament;
- ordinary left/right locomotion;
- exceptional movement only when source-supported;
- quiet personal/daily actions for long desktop use;
- defining prop or signature interactions;
- restrained small abilities;
- one or more source-owned signature abilities where they add distinct meaning;
- safe entry, interruption, recovery, and return.

Every selected action must add a distinct silhouette, energy level, timing pattern, or character meaning. The runtime minimum is only a loadability floor.

### 4. Separate ordinary and exceptional movement

Ordinary movement must look sustainable and cyclic. A standing or idle body translated across the screen is a concept failure.

Exceptional movement must be a different action family: anticipation → acceleration/transformation → travel → arrival → recovery. World position changes only during declared travel frames. Its useful distance must be visibly greater than ordinary movement, its frequency lower, and edge behavior safe through inward selection or destination clamping.

Movement distance should normally be relative to usable screen width. Historical pixel values may be calibration points, never universal requirements.

### 5. Prove every planned risk class

Before batch production, pass one representative pilot for each planned class:

| Risk class | Pilot must prove |
|---|---|
| Identity/idle | Recognition, body scale, alpha, anchor, breathing/blink cadence. |
| Prop interaction | Introduction, ownership, hand contact, occlusion, use, and disappearance. |
| Cyclic locomotion | Travel silhouette, directional design, cloth/hair response, and loop seam. |
| Burst/transformation | Anticipation, travel-only displacement, endpoint recovery, distance, and edges. |
| Large/layered effect | Caster ownership, body readability, canvas/layer strategy, peak, and cleanup. |
| Form/sequence | Enter, resident, exit, safe stop, restore, and cleanup. |

One successful action does not authorize a different risk class. Use a high-information pilot when possible: it should exercise identity, hands or cloth, occlusion, timing holds, alpha extraction, atlas mapping, and motion review.

### 6. Make semantic key poses, then dynamic frames

Write the action as phases before assigning frames:

`entry/anticipation → preparation → development → peak → semantic hold → release/decay → recovery → return`

Use only the phases the action needs. Create an independent key pose whenever anatomy, body direction, hand state, depth/occlusion, garment, prop, effect structure, or form changes. Add intermediates only between structurally stable neighbors.

Frame count follows semantic events. Per-frame duration follows meaning: quick transitions stay quick; readable peaks and personal gestures may hold. Never duplicate near-identical frames, shift the whole sprite, or use interpolation to conceal missing acting or anatomy.

Props follow `absent → introduced → acquired → used → released/consumed → absent`. Effects follow `origin → growth/travel → peak → decay → cleanup`.

### 7. Keep the character larger than the spectacle

Judge body occupancy independently from full effect extent. A large effect must not shrink the approved character body. First redesign composition, cropping, timing, or effect extent. If one bounded attempt cannot preserve both required effect meaning and body readability in the chosen route, keep the action blocked and reconsider the package architecture.

Fixed-canvas registration removes accidental jitter. It must preserve intentional hovering, vertical arcs, recoil, and other source-supported body motion.

### 8. Separate generative and deterministic work

Generative output creates identity or storyboard candidates. Deterministic tooling owns background removal, alpha cleanup, slicing, fixed-canvas registration, layer composition, frame order, atlas assembly, manifest geometry, contact sheets, and true-duration previews.

Every generated grid is inspected cell by cell. Targeted repairs preserve unaffected cells. A concept failure returns to a new key pose; a local hand/face/prop error receives a targeted edit; a pipeline error is repaired in tooling.

### 9. Validate stills, motion, runtime, and behavior separately

Every action needs:

- a manifest-order labeled contact sheet;
- actual-size checker, light, and dark renders;
- a true-duration loop or one-shot preview;
- in-app review at normal scale when authorized.

Then validate schema, WebP/alpha, mappings, Registry, Catalog, menu/manual paths, automatic eligibility, direction, movement boundaries, interruption, recovery, and actual launched logs.

Schedule importance separately from frequency. Iconic actions may be always available manually and rare automatically. Ordinary locomotion is frequent; exceptional travel is rare; quiet daily actions normally dominate stationary autoplay; large spectacle needs low weight, cooldown, and anti-streak behavior where the runtime supports it.

### 10. Observe, repair causally, and stop

After formal gates pass, observe normal desktop use for 30–60 minutes or the approved soak period. Record repetition, dominance, actions that never appear, rare actions that are too brief to notice, background readability, screen-edge behavior, interruption, recovery, and logs.

Repair the causal layer, rerun affected downstream gates, and stop adding content when identity, coverage, visual, runtime, behavior, and long-use gates pass. “More actions are possible” is not evidence of improvement.

## Nangong Wan calibration record

These historical values explain the scale of the validated work; they are not a recipe:

| Area | Historical calibration |
|---|---|
| Portfolio | 19 actions: 1 idle, 2 ordinary moves, 2 burst moves, 7 daily interactions, 7 spell interactions. |
| Production volume | 174 referenced key frames at the pre-gaze cutoff. |
| High-information pilot | Veil interaction: 10 frames, about 2.09 seconds, peak hold about 550 ms. |
| Burst movement | 10 frames, about 1.2 seconds; travel concentrated around frames 3–7; about half of usable screen width. |
| Burst scheduling | Ordinary-to-burst nominal movement weight about 19:1, with edge protection and a long cooldown. |
| Stationary behavior | Daily actions carried most automatic presence; spells were lower-weight and cooldown/group constrained. |
| Technical growth | Passing test counts rose across iterations, but visual failures still required redraw or recomposition. |
| Stop decision | At roughly 9/10, the next correct step was real-use observation rather than blind action expansion. |

## Proven failure-and-repair rules

| Failure | Required repair |
|---|---|
| Older appearance governs the requested current character | Re-lock the current era; keep old footage only as compatible motion grammar. |
| Flight reads as standing art sliding | Redraw locomotion key poses. Timing and interpolation cannot repair the concept. |
| Burst is too short or too close to ordinary movement | Make its phases and useful distance perceptible, then lower its frequency. |
| All actions inherit fixed rows, frame counts, or timing | Move labels, frames, durations, and behavior to dynamic per-action contracts. |
| Large effects make the person smaller | Restore body occupancy; redesign composition/layers/route. |
| Alignment removes deliberate hover motion | Restore fixed-canvas intentional anchor motion. |
| Tests pass but the action looks wrong | Keep runtime evidence; block visual acceptance and repair the causal visual layer. |
| A signature action is hidden from autoplay because it is powerful | Keep eligibility separate from rarity; use weight, cooldown, group, and manual access. |
| Coverage is already broad but more actions are tempting | Soak the current pet and change only observed failures. |

## Transfer rule

For every later character, explicitly write:

- what is copied from this standard: decision order, gates, artifact chain, repair and stop logic;
- what is newly derived from that character's evidence: identity, actions, effects, frame counts, timings, movement, weights, and cooldowns.

If a plan uses the second list without first applying the first list, it is not following the Nangong Wan quality standard.
