# Handoff Contracts

Use these compact reports for work performed by any capable worker or parent. Do not require a named custom agent.

## Research report

- `STATUS`: `READY` or `BLOCKED`.
- `TARGET`: exact package or new-package scope; format status and isolation evidence.
- `EVIDENCE`: sources, observed facts, allowed/denied use, uncertainty, provenance statuses, and `selection: candidate|selected`.
- `SOURCE_CAPABILITY_INVENTORY`: forms, transformations, locomotion, interactions, gaze, props, effects, quality variants, sequences, restoration, autoplay relationships, and uncertainties that could affect the version.
- `VERSION_RECOMMENDATION`: preferred v2/v3/v4 route, evidence, fidelity preserved or omitted by each viable route, complexity, extensibility, and unresolved uncertainty.
- `FORMAT_CONFIRMATION`: for a new package or migration, record the exact post-research user instruction that selected a version after the recommendation; use `PENDING` before confirmation and record any earlier version request as an initial preference only. For a repair that retains its detected version, record `N/A — detected <version> retained`.
- `IDENTITY`: identity master with provenance status and selection, proportion route, silhouette, palette, costume, asymmetry, props, and form matrix.
- `ACTION_FORM_CONTRACT`: action/form requirements, transitions, runtime semantics, acceptance checks, provenance statuses (`REQUIRED`/`DERIVED`/`PROPOSED`/`APPROVED`), and `selection: candidate|selected` for every recorded value.
- `NEXT_GATE`: user format confirmation only when `FORMAT_CONFIRMATION` is `PENDING`; otherwise the smallest artifact or decision needed to proceed.

## Build report

- `STATUS`: `READY_FOR_REVIEW` or `BLOCKED`.
- `SELECTED_INPUTS`: evidence, confirmed package version, masters, contracts, immutable comparison set, provenance statuses, and selections actually used.
- `SCOPE`: exact files changed; confirm unrelated dirty work and immutable assets remained untouched.
- `OUTPUTS`: masters, key frames, extracted assets, atlases, mappings, contact boards, and previews.
- `VALIDATION`: exact commands, exit codes, tests, hashes, and visual/runtime checks performed.
- `UNVERIFIED`: every skipped or unavailable check and why.
- `NEXT_GATE`: reviewer input set or exact blocker.

## Review report

- `VERDICT`: exactly `PASS` or `BLOCKED`.
- `VALIDATED`: artifacts, references, target isolation, selected-version tests, Registry/Catalog/runtime evidence, and visual gates actually inspected.
- `BLOCKERS`: source, identity, visual, configuration, runtime, or authority blockers with action/form/frame evidence.
- `FINDINGS`: serious defects and non-blocking polish, each with provenance status and selection where relevant.
- `MINIMUM_REWORK`: smallest master, action, interval, layer, configuration, or test scope to repeat.
- `LIMITATIONS`: checks not performed and external authority not granted. If the request explicitly requires user approval, or an unresolved subjective ambiguity has no safe evidence-based resolution, record it as a `BLOCKER`; it cannot be waived as a limitation.
