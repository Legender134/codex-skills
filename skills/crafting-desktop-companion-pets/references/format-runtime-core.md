# Format and Runtime Core

This is the retained core of the earlier general Skill. Use it after the Nangong Wan quality standard has established what fidelity the character needs.

## Version gate

For a new package or migration, research capabilities first, recommend a route with preserved/omitted fidelity and complexity, then obtain explicit user confirmation before locking the schema, atlas/layer architecture, final action contract, or batch production.

For an existing package, retain its detected version for repair unless required fidelity justifies a separately confirmed migration.

| Route | Use |
|---|---|
| v2 | Repair an existing fixed 8×11, 192×208 atlas that does not require migration. |
| v3 | New or existing single-form pet with one dynamic transparent atlas. Action count alone does not require v4. |
| v4 | Required layers/wide effects, full/simplified quality, forms, transformations, sequences, restoration, or bucket/shared-cooldown semantics. |

Read the current repository's governing format document and executable source. Build a capability map for action types, menus, automatic pools, timings, movement semantics, cooldown/groups, interruption, and recovery. Do not invent fields or use duplicate interactions to imitate unsupported behavior.

## High-value invariants

| Version | Verify |
|---|---|
| v2 | Directory/ID; `spriteVersionNumber: 2`; transparent 1536×2288 WebP; fixed 8×11 cells of 192×208; required slots and non-empty referenced cells. |
| v3 | Directory/ID; one transparent `spritesheet.webp`; 192×208 cell multiples; exactly one looping idle, left/right move, and at least one interaction; valid non-empty mappings; mirror only when asymmetry permits. |
| v4 | Case-sensitive ID/directory and camelCase keys; 1–8 valid atlases; one body/hit-test layer per action; stable anchors; full/simplified validation; idle and moves per form; only default-form gaze; exit for non-default forms. |

For v4 also validate enter/resident/exit, sequence repeats/holds, `formAfter`, safe stop, pending, restore, idempotent cleanup, bucket eligibility, weights, shared cooldown accounting, and manual versus automatic start.

## Runtime acceptance

Run the selected schema and current repository tests, then verify WebP decode/alpha, cell availability, cross-references, Registry, Catalog, menu/manual paths, scheduler behavior, boundaries, interruption/recovery, and applicable form/quality/sequence behavior.

Resolve logs and operational paths from the actual launched build. Documentation disagreement is evidence to inspect the executable path, not permission to accept a package because another pet loads.

Schema success proves shape only. It does not prove identity, visual quality, decode, runtime admission, scheduler behavior, or in-app experience.

## Scope and authority

Source-faithful creation/review includes read-only public research needed for evidence unless the user explicitly forbids browsing. It does not authorize:

- reusable-asset downloads;
- built-in integration or live installation;
- commits, pushes, publication, releases;
- logged-in/account actions;
- global configuration.

Obtain explicit authority for each persistent or external mutation. Stop with the exact blocker when target identity, evidence, write scope, required format confirmation, or a visual/runtime gate cannot be established.
