# Repair and Convergence

Read this after a failed gate or repeated candidate failure. It owns causal
repair selection and convergence; [Generation Job Graph](generation-job-graph.md)
owns state transitions and descendant traversal.

## Diagnose the failing layer

| Failure class | Minimum causal repair |
|---|---|
| Identity, era, costume, ability, caster, or palette | replace target evidence or rebuild the canonical identity |
| Visual semantics, locomotion, silhouette, or major pose | redraw semantic key poses or the complete action |
| Local hand, face, contact, prop, or effect transition | targeted frame repair and adjacent-frame review |
| Continuity in a structurally stable interval | limited intermediate frame work |
| Source geometry, alpha/chroma, extraction, crop, order, registration, or anchor | deterministic pipeline repair |
| Format, menu, timing, mapping, weight, distance, cooldown, interruption, or recovery | format adapter, manifest, or runtime behavior repair |
| Behavior or authority | repair the missing scheduler/runtime evidence or stop for authority |

Record visible evidence, root condition, exactly one changed variable, preserved
passing properties, before/after result, and next strategy. Preserve the
last-valid artifact hash so a local repair does not cause unrelated rework.

## Change strategy after recurrence

After the same failure class and root condition recur twice, do not merely vary
prompt wording. Change a causal input: reference evidence, semantic key poses,
layout/composition, generation granularity, or production route. Continue a
user-requested attempt only with that changed strategy; do not lower an
acceptance gate to finish a batch.

## Re-run only affected claims

Repair at the layer that caused the failure, then rerun that gate and each
downstream claim invalidated by its changed artifact hash. Keep independent,
unaffected evidence. See [Visual QA](visual-qa.md) for gate evidence and
[Generation Job Graph](generation-job-graph.md) for selected-hash dependency
rules.

## Stop when a blocker is real

Stop with the exact blocker when target identity, evidence, write scope, format
confirmation, a required visual/runtime gate, or authority cannot be
established. More candidates, test count, or a successful unrelated pilot is
not evidence that the blocker is resolved.
